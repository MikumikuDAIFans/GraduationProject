# 项目任务书

**更新日期**: 2026-04-18  
**当前基线**: 以当前工作区代码为准  
**当前判断**: 项目处于 **V6 在建，附带少量 V7 前置改造** 状态

## 当前目标

把当前“半成品 + 多版本并行施工”的状态收束成一个可稳定继续开发和汇报的基线，明确：

- 哪些 V6 能力已经真正落地
- 哪些只是代码草稿/测试草稿
- 是否继续推进 V7，还是先收口 V6

## 当前完成情况

### 已稳定存在于主链路/主界面的部分

- 事件、任务、提醒、助手会话等基础业务链路已存在
- Assistant 已支持 WebSocket 流式回复
- 助手当前会话、Inbox、Summary 等接口已存在
- 地图、天气、Google Calendar、提醒、WebSocket 主工作台链路仍在使用
- 前端 Store 拆分已完成大部分结构迁移，`workspace.ts` 已退化为兼容层
- 移动端/桌面端壳目录已建好

### 已进入代码库但尚未完全接通的 V6 施工内容

- 向量库与 Gemini Embedding
- 习惯学习/偏好学习服务
- 多轮对话槽位补全
- 扫描线冲突检测器
- 智能任务拆分服务
- Habit / TaskSplit 数据模型及迁移草稿

### 已出现但尚未接管主流程的 V7 施工内容

- LangGraph 工作流目录
- ReAct 子图
- 条件化上下文收集节点
- 工具注册型写法
- 部分超时与外部上下文优化

## 当前关键判断

### 当前版本归属

- 不是 V7 完成态
- 不是 V5 或更早
- 应归类为：**V6 进行中，夹带部分 V7 改造**

### 当前主问题

项目并不是“没有新能力”，而是“新能力很多，但没有完全收口到一个清晰可运行版本”。

## 关键决策

### 已确认

1. 当前项目需要先做**版本核对与文档校准**，而不是继续无序扩展。
2. `development/` 与 `project-management/` 文档需要以当前代码状态重写。
3. 文档必须明确区分：
   - 已进入主链路
   - 已写代码但未接通
   - 仅存在于计划/测试层

### 建议锁定

1. 近期优先目标应是**收口 V6**，而不是同时继续做 V7。
2. 在 V6 主链路接通前，不建议再继续扩展新的工作流分支或新数据结构。

## 当前风险

1. `AssistantService` 仍然过大，真实主链路与新工作流代码并存。
2. V6 模型与 Alembic 迁移存在不一致。
3. 部分新服务已经暴露 API，但实现仍有字段/依赖不匹配问题。
4. 测试报告与当前环境可复现结果不完全一致。
5. 工作区存在大量未提交改动，说明当前状态更接近“开发现场”而不是“稳定版本”。

## 下一步任务

### P0

1. 统一版本口径
   - 对外统一表述为“V6 在建，附带少量 V7 前置改造”
2. 收口 V6 主链路
   - 决定哪些 V6 能力必须真正接入 `AssistantService`
3. 修正数据层不一致
   - 对齐 ORM、迁移、Schema、测试

### P1

1. 校准智能任务拆分链路
   - 让 `split-suggestions` 从“接口已出现”变成“可稳定可演示”
2. 校准习惯学习链路
   - 明确最小可用链路：采集、检索、建议、展示
3. 重新跑通测试基线
   - 让“文档中的测试结论”可在当前环境复现

### P2

1. 决定是否进入 V7 正式切换
   - 若进入，则必须先完成 workflow 接管主入口
2. 若暂不进入 V7
   - 将 workflow / react 代码标记为预研或下一阶段能力

## 当前建议的唯一下一步动作

先以 **V6 收口** 为目标做一次实现级清理：

1. 明确 V6 必须保留的能力清单
2. 接通真正需要的主链路
3. 暂停未接通的 V7 分支扩散
